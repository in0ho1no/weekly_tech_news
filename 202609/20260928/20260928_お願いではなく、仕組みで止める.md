# お願いではなく、仕組みで止める

## きっかけ

コーディングエージェントを使い始めた人から、「AIの挙動を抑止する手段を知りたい」という声を何度か聞きました。  
CLAUDE\.mdやcopilot-instructions\.mdに「やらないで」と書いても、確実に守られるわけではない、という体験が背景にあるようです。  

この記事では、その手段の1つであるhooks（フック）を紹介します。  
対象はClaude CodeとVS Code上のGitHub Copilotです。  
実行前フックで`git push --force`を止める設定と、止まるかどうかを安全に確かめる方法を説明します。  
整形やログ取りなど、実行後のフックは扱いません。  

:::caution
この記事は2026年9月24日時点の公式ドキュメントを参照しています。
確認できた動作と、実機での検証が必要な箇所は分けて記載します。
:::

## 仕組みの概要

### カスタムインストラクションは「お願い」、hooksは「仕組み」

CLAUDE\.mdやcopilot-instructions\.mdは、AIが読んで判断に使う文章です。  
「force pushしないで」と書けば多くの場合は従いますが、判断するのはAIです。  
ロングセッションや文脈によっては読み落としたり判断を誤ったりすることがあります。  

hooksは、設定が読み込まれると、「ツールを実行する直前」のような決まったタイミングでスクリプトを呼び出します。  
スクリプトが対象を検出し、クライアントに合った形式で「拒否」を返せば、AIの判断とは別にそのツール呼び出しを止められます。  
ただし、設定ミスやタイムアウト時まで止められるわけではありません。  

| | カスタムインストラクション | hooks |
| --- | --- | --- |
| 誰が判断するか | AI | 自分が書いたスクリプト |
| 判断の条件 | AIが指示を参照して判断する | フックが動作し、拒否応答が解釈されれば止まる |
| 向いている用途 | 方針・書き方・優先順位 | 特定の操作を実行前に検出して遮断する |

両者は置き換えではなく、役割分担です。  
カスタムインストラクションには方針を、hooksには「これだけは止める」を置く、という使い方になります。  

### 実行前フックで止められるもの

実行前フック（PreToolUse）は、対象のツール呼び出し前に、ツール名と引数をJSONでスクリプトに渡します。  
スクリプトはそれを見て、対象なら拒否し、対象外なら通常の権限確認に任せます。  

止める対象の例を挙げます。  

- 破壊的なコマンド：`rm -rf`、`Remove-Item -Recurse`、`git reset --hard`
- 取り消せないリモート操作：`git push --force`、ブランチの削除
- 秘密情報の読み取り：`.env`や認証情報ファイルの参照
- 特定ディレクトリ外への書き込み

どれも「AIが間違えたときに戻せない」か「戻せても被害が出る」操作です。  
逆に、戻せる操作（作業ツリー内のファイル編集など）はフックで止めるより、レビューで拾う方が実用的です。  

## Claude Codeでの実例

設定は`.claude/settings.json`、判定スクリプトは`.claude/hooks/`に置きます。  
前者で実行するタイミングとコマンドを指定し、後者で拒否する条件を判定します。  
ここではWindowsでPowerShellを使う例を示します。各自の環境でも最後の手順で動作を確認してください。  

### 設定

まず設定`.claude/settings.json`の例を示します。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "powershell.exe",
            "args": [
              "-NoProfile",
              "-ExecutionPolicy",
              "Bypass",
              "-File",
              "${CLAUDE_PROJECT_DIR}/.claude/hooks/guard.ps1"
            ]
          }
        ]
      }
    ]
  }
}
```

`matcher`で「BashツールまたはPowerShellツールが呼ばれたとき」に絞っています。  
`args`を使う書き方（exec形式）は、シェルを介さず直接スクリプトを起動するので、パスに空白があっても壊れません。  

### 判定スクリプト

続いて判定スクリプト`.claude/hooks/guard.ps1`の例を示します。

```powershell
param([switch]$Copilot)

# 標準入力のJSONを読む
$raw = [Console]::In.ReadToEnd()
try { $in = $raw | ConvertFrom-Json -ErrorAction Stop } catch {
  [Console]::Error.WriteLine("Invalid hook input: $_")
  exit 2
}

# ツールの引数にcommandが無ければ、この例では判定対象外
$cmd = $in.tool_input.command
if (-not $cmd) { exit 0 }

# force push を止める ※ 意図的に単純なパターンにしています。
if ($cmd -match 'git\s+push\b.*(\s-f\b|\s--force\b)') {
  if ($Copilot) {
    @{
      permissionDecision       = "deny"
      permissionDecisionReason = "force push is blocked by hook. Run it manually if really needed."
    } | ConvertTo-Json -Compress
  } else {
    @{
      hookSpecificOutput = @{
        hookEventName            = "PreToolUse"
        permissionDecision       = "deny"
        permissionDecisionReason = "force push is blocked by hook. Run it manually if really needed."
      }
    } | ConvertTo-Json -Compress -Depth 3
  }
  exit 0
}

# 判定なし。通常の権限フローに任せる
exit 0
```

Claude Codeで止めるときは`hookSpecificOutput.permissionDecision: "deny"`のJSONを標準出力に書きます。  
`-Copilot`を付けた場合は、Copilot側が解釈するトップレベルの`permissionDecision`を返します。  
止めないときは何も出力せず終了コード0で終わります。  
これは「許可」ではなく「判定なし」で、そのあと通常の権限確認に進みます。  
JSONの解析に失敗した場合はエラーを出して終了コード2で止めます。ただし、コマンド文字列を取得できなければ、この例では対象外として通します。  

:::info
`permissionDecisionReason`はAIにも返され、次の行動の材料になります。
Windowsの標準出力の文字コードの影響を避けるため、ここでは英語で書いています。
:::

## VS Codeでの扱い

VS Code上のCopilotには「Session Target」という選択があり、選んだ先によってhooksの実装が変わります。  
設定を書く前に、使っているSession Targetを確認してください。  
なお、VS Codeのhooks機能そのもの（設定画面や読み込みの仕組み）は、Session Targetによらずプレビュー扱いです。  

![Session Targetがローカルの状態](img/image-1.png)

本記事ではローカルとCopilotの両方を扱います。  

![Session TargetがCopilotの状態](img/image-2.png)

| Session Target | hooks実装 | 設定ファイル | 状態 |
| --- | --- | --- | --- |
| ローカル | VS Code独自 | `.github/hooks/*.json` | Preview |
| Copilot | Copilot SDK（Copilot CLIと同じ） | `.github/hooks/*.json`、`.claude/settings.json`も読む | GA |

:::info
イベント名の大文字小文字に意味があります。
GitHub Docsでは`preToolUse`と小文字始まりで書きますが、Copilotで`PreToolUse`と大文字始まりにするとClaude Code形式の`matcher`やツール名が使われ、入力項目名も`tool_input`などの形式になります。
この記事では実装間の違いを比較しやすいよう、イベント名を`PreToolUse`で統一しています。
:::

### ローカル

設定を`.github/hooks/guard.json`に置きます。  

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .github/hooks/guard.ps1",
        "timeout": 15
      }
    ]
  }
}
```

スクリプトは前述の`guard.ps1`をそのまま`.github/hooks/`にコピーします。  
ローカルは`matcher`を無視し、すべてのツール呼び出しでフックが走ります。  
スクリプトの側で「`tool_input.command`が無ければ対象外」としているのは、このためです。  
ツール名の違いは見ず、コマンド文字列の有無だけで判定します。  

止めるときの出力形式（`hookSpecificOutput.permissionDecision`）はClaude Codeと同じです。  
一方、同じ設定ファイルをCopilot側でも読み込ませる場合、出力形式が異なるため、スクリプトをそのまま流用しないでください。  

### Copilot

Session TargetをCopilotにした場合は、Copilot CLIと同じhooks実装が動きます。  
公式ドキュメントでは、`.claude/settings.json`の読み込みに加えて、`.github/hooks/*.json`内で`PreToolUse`を使う場合もClaude Code形式の`matcher`（`Bash`など）として解釈すると説明されています。  
ただし、`tool_input`はツールの引数であり、その中に`command`があるかどうかは対象ツール次第です。  

設定は`.github/hooks/guard.json`に次のように置けます。  
判定スクリプトは前述のものを`.github/hooks/guard.ps1`にコピーし、Copilot向けの拒否形式を返すため`-Copilot`を付けます。  

```json
{
  "version": 1,
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "matcher": "Bash",
        "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .github/hooks/guard.ps1 -Copilot",
        "timeoutSec": 15
      }
    ]
  }
}
```

ローカルとCopilotはどちらも`.github/hooks/*.json`を読みます。上の設定とローカル用の設定を同じリポジトリに同時に置くと、意図しないフックも実行されます。まずは別々の確認用フォルダで試してください。  
Copilotの`tool_input`に`command`が入らない呼び出しは、このサンプルでは止まりません。最後の手順で実際に拒否されることを確認し、止まらなければ選択中のSession Targetとフックの入力・出力を確認してください。  

:::source
VS Code Docs「Configure agent hooks in Visual Studio Code」
<https://code.visualstudio.com/docs/agent-customization/hooks>

GitHub Docs「GitHub Copilot hooks reference」
<https://docs.github.com/en/copilot/reference/hooks-reference>
:::

## 限界

### パターンマッチはすり抜けられる

上のスクリプトは`git push --force`の文字列を見ているだけです。  
`git push origin +main`のような別の書き方や、変数展開、スクリプトファイル経由の実行には反応しません。  

文字列だけを検査するフックでは、コマンドの別表記や間接的な実行まで網羅できません。  
OpenAIもCodexのhooks文書で「hooksは有用なガードレールであって、完全な強制境界ではない」と明記しています。  

そのため、本当に止めたい操作は、hooksだけに頼らず次と組み合わせます。  

- 権限設定のdeny：  
Claude Codeなら`settings.json`の`permissions.deny`。  
公式も、確実な許可・拒否には権限設定を使うよう案内しています
- サンドボックス：  
OSレベルでファイルやネットワークを制限する仕組み。  
各ツールが提供しています

hooksは「権限設定では書きにくい条件」を補う位置づけです。  

### フックが止まらないケース

設定したつもりで効いていない、という失敗も起こります。  
公式ドキュメントに書かれている代表例を挙げます。  

- スクリプトのパスが間違っている：  
Claude Codeでは警告が出るだけで、ツール呼び出しは進みます。
- 終了コード1で終わっている：  
Claude Codeで止まるのは終了コード2か`deny`のJSONだけです。  
一方Copilot（Session Target=Copilot）では異常終了すると止まります。  
正常な判定結果は、それぞれに合ったJSONで`deny`を返します。
- タイムアウト：  
どのツールでも、時間切れのフックは止めません。
- Session Targetの違い：  
VS Codeで、設定した先と使っている先が違うと動きません。

Codex Docs「Hooks」
<https://developers.openai.com/codex/hooks>
:::

## hooks自体が任意のコマンドを実行する

hooksは、リポジトリに置いた設定ファイルから、任意のコマンドを起動する仕組みです。  
つまり、他人のリポジトリをクローンしてエージェントを起動すると、**その人が書いたスクリプトが自分のPCで動く**ことになります。  

各ツールはこの点を意識していて、VS CodeはWorkspace Trust、Codexはフック定義ごとのレビューと信頼を挟みます。  
それでも、確認するのは自分です。  

- 他人のリポジトリの`.claude/settings.json`や`.github/hooks/`は、エージェントを起動する前に中身を読む
- フックのスクリプトをAIが編集できる状態にしない。編集されると、次の呼び出しからその内容で動きます

skillsの回で書いた「配布元を確認する」と同じ話です。  
実行されるものが指示文からスクリプトに変わった分、影響は直接的になります。  

## 試してみる

フックを1つだけ入れて、わざと引っかけて止まることを確認します。  
効いているかどうかは、止まるまで分かりません。  

1. 空のフォルダで`git init`し、適当なファイルを1つコミットする。リモートは設定しない
2. 試すツールやSession Targetに対応する設定とスクリプトを置く。ローカル用とCopilot用の設定は同時に置かない
3. エージェントに`git push --force origin main`を実行するよう頼む

拒否理由が表示され、コマンドが実行されなければ成功です。  
止まらなければ、上の「フックが止まらないケース」を順に確認します。  
Claude Codeでは`/hooks`で読み込まれた設定を確認できます。  
VS CodeではSession Targetを選び、チャット画面の歯車アイコンから「Configure Chat」→「Hooks」を開きます。Agentsウィンドウなら「Customizations」→「Hooks」、チャット入力欄からは`/hooks`でも開けます。  
入力の`tool_input`に`command`が無い場合も、この例では止まりません。  

:::tip
リモートを設定していないので、仮にフックが効いていなくても`git push`は失敗するだけです。
確認用の環境で試してから、実際のリポジトリに入れてください。
:::

hooksは、入れれば安心になる道具ではありません。  
何を止めたいかを自分で決めて、止まることを自分で確かめる。  
その手間の分だけ、AIに任せられる範囲が広がります。
