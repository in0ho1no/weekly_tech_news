# お願いではなく、仕組みで止める

## きっかけ

コーディングエージェントを使い始めた人から、「AIの挙動を抑止する手段を知りたい」という声を何度か聞きました。  
CLAUDE\.mdやcopilot-instructions\.mdに「やらないで」と書いても、確実に守られるわけではない、という体験が背景にあるようです。  

この記事では、その手段の1つである**hooks**を紹介します。  
対象はClaude CodeとVS Code上のGitHub Copilotで、扱うのは「ツールの実行前に止める」フックだけです。整形やログ取りなど、実行後のフックは扱いません。  

:::caution
hooksの仕様は変わりやすい機能です。
この記事の内容は2026年9月24日時点の公式ドキュメントと実機確認に基づきます。
:::

## 指示ファイルは「お願い」、hooksは「仕組み」

CLAUDE\.mdやcopilot-instructions\.mdは、AIが読んで判断に使う文章です。  
「force pushしないで」と書けば多くの場合は従いますが、判断するのはAIです。文脈によっては別の判断をすることがあります。  

hooksは違います。  
「ツールを実行する直前」のような決まったタイミングで、あらかじめ用意したスクリプトが**必ず**実行されます。AIの判断を介しません。  
スクリプトが「拒否」を返せば、そのツール呼び出しはAIの意思に関係なく実行されません。  

| | 指示ファイル | hooks |
| --- | --- | --- |
| 誰が判断するか | AI | 自分が書いたスクリプト |
| 守られる確率 | 高いが100%ではない | パターンに一致すれば必ず止まる |
| 向いている用途 | 方針・書き方・優先順位 | 絶対にやらせたくない操作の遮断 |

両者は置き換えではなく、役割分担です。  
指示ファイルには方針を、hooksには「これだけは止める」を置く、という使い方になります。  

## 実行前フックで止められるもの

実行前フック（PreToolUse）は、AIがツールを呼ぶたびに、ツール名と引数をJSONでスクリプトに渡します。  
スクリプトはそれを見て、通すか止めるかを返します。  

止める対象の例を挙げます。  

- 破壊的なコマンド：`rm -rf`、`Remove-Item -Recurse`、`git reset --hard`、`git clean -fd`
- 取り消せないリモート操作：`git push --force`、ブランチの削除
- 秘密情報の読み取り：`.env`や認証情報ファイルの参照
- 特定ディレクトリ外への書き込み

どれも「AIが間違えたときに戻せない」か「戻せても被害が出る」操作です。  
逆に、戻せる操作（作業ツリー内のファイル編集など）はフックで止めるより、レビューで拾う方が実用的です。  

## Claude Codeでの実例

設定は`.claude/settings.json`、判定スクリプトは`.claude/hooks/`に置きます。  
ここではWindows前提でPowerShellを使います。  

### 設定

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "powershell.exe",
            "args": [
              "-NoProfile",
              "-ExecutionPolicy",
              "Bypass",
              "-File",
              "${CLAUDE_PROJECT_DIR}/.claude/hooks/guard.ps1"
            ]
          }
        ]
      }
    ]
  }
}
```

`matcher`で「BashツールまたはPowerShellツールが呼ばれたとき」に絞っています。  
`args`を使う書き方（exec形式）は、シェルを介さず直接スクリプトを起動するので、パスに空白があっても壊れません。  

### 判定スクリプト

`.claude/hooks/guard.ps1`

```powershell
# 標準入力のJSONを読む
$raw = [Console]::In.ReadToEnd()
try { $in = $raw | ConvertFrom-Json } catch { exit 0 }

# コマンド文字列が無いツール呼び出しは対象外
$cmd = $in.tool_input.command
if (-not $cmd) { exit 0 }

# force push を止める
if ($cmd -match 'git\s+push\b.*(\s-f\b|\s--force\b)') {
  @{
    hookSpecificOutput = @{
      hookEventName            = "PreToolUse"
      permissionDecision       = "deny"
      permissionDecisionReason = "force push is blocked by hook. Run it manually if really needed."
    }
  } | ConvertTo-Json -Compress -Depth 3
  exit 0
}

# 判定なし。通常の権限フローに任せる
exit 0
```

止めるときは`permissionDecision: "deny"`のJSONを標準出力に書きます。  
止めないときは何も出力せず終了コード0で終わります。これは「許可」ではなく「判定なし」で、そのあと通常の権限確認に進みます。  

:::info
`permissionDecisionReason`はAIにも返され、次の行動の材料になります。
Windowsの標準出力の文字コードの影響を避けるため、ここでは英語で書いています。
:::

:::source
Claude Code Docs「Hooks reference」
<https://code.claude.com/docs/en/hooks>
:::

## VS Codeでの扱い

VS Code上のCopilotは、2026年9月時点で「Session Target」という選択があり、選んだ先によってhooksの実装が変わります。  
これまで使ってきた通常のCopilot Chat（エージェントモード）は**Local**です。  

| Session Target | hooks実装 | 設定ファイル | 状態 |
| --- | --- | --- | --- |
| Local | VS Code独自 | `.github/hooks/*.json` | Preview |
| Copilot | Copilot SDK（Copilot CLIと同じ） | `.github/hooks/*.json`、`.claude/settings.json`も読む | 実装はGA、VS Codeの入口はPreview |

:::info
イベント名の大文字小文字に意味があります。
GitHub Docsでは`preToolUse`と小文字始まりで書きますが、`PreToolUse`と大文字始まりで書くとClaude Code形式として解釈され、`matcher`やツール名もClaude Codeのものが使われます。
この記事では設定を共有しやすいよう、全体を`PreToolUse`で統一しています。
:::

### Local

設定を`.github/hooks/guard.json`に置きます。  

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "command": "powershell -NoProfile -ExecutionPolicy Bypass -File .github/hooks/guard.ps1",
        "timeout": 15
      }
    ]
  }
}
```

スクリプトは前述の`guard.ps1`をそのまま`.github/hooks/`にコピーします。  
Localは`matcher`を無視し、すべてのツール呼び出しでフックが走ります。  
スクリプトの側で「`tool_input.command`が無ければ対象外」としているのは、このためです。ツール名の違いは見ず、コマンド文字列の有無だけで判定します。  

止めるときの出力形式（`hookSpecificOutput.permissionDecision`）はClaude Codeと同じです。  

### Copilot

Session TargetをCopilotにした場合は、Copilot CLIと同じhooks実装が動きます。  
公式ドキュメントでは、Claude Code形式の`.claude/settings.json`を読み、`matcher`もClaude形式のツール名（`Bash`など）で解釈すると説明されています。  
ただし、`tool_input`の中身がClaude Codeと同じ形かは文書に明記がなく、この記事では実機確認していません。  

:::source
VS Code Docs「Configure agent hooks in Visual Studio Code」
<https://code.visualstudio.com/docs/agent-customization/hooks>

GitHub Docs「GitHub Copilot hooks reference」
<https://docs.github.com/en/copilot/reference/hooks-reference>
:::

## 限界

### パターンマッチはすり抜けられる

上のスクリプトは`git push --force`の文字列を見ているだけです。  
`git push origin +main`のような別の書き方や、変数展開、スクリプトファイル経由の実行には反応しません。  

これはこのスクリプトが雑だからではなく、実行前フックという仕組みの性質です。  
OpenAIもCodexのhooks文書で「hooksは有用なガードレールであって、完全な強制境界ではない」と明記しています。  

そのため、本当に止めたい操作は、hooksだけに頼らず次と組み合わせます。  

- 権限設定のdeny：Claude Codeなら`settings.json`の`permissions.deny`。公式も、確実な許可・拒否には権限設定を使うよう案内しています
- サンドボックス：OSレベルでファイルやネットワークを制限する仕組み。各ツールが提供しています

hooksは「権限設定では書きにくい条件」を補う位置づけです。  

### フックが止まらないケース

設定したつもりで効いていない、が最も起きやすい失敗です。  
公式ドキュメントに書かれている代表例を挙げます。  

- スクリプトのパスが間違っている：Claude Codeでは警告が出るだけで、ツール呼び出しは進みます
- 終了コード1で終わっている：Claude Codeで止まるのは終了コード2か`deny`のJSONだけです。一方Copilot（Session Target=Copilot）では異常終了すると止まります。ツールによって逆なので、JSONで`deny`を返す方式に揃えると安全です
- タイムアウト：どのツールでも、時間切れのフックは止めません
- Session Targetの違い：VS Codeで、設定した先と使っている先が違うと動きません

:::source
Codex Docs「Hooks」
<https://developers.openai.com/codex/hooks>
:::

## hooks自体が任意のコマンドを実行する

hooksは、リポジトリに置いた設定ファイルから、任意のコマンドを起動する仕組みです。  
つまり、他人のリポジトリをクローンしてエージェントを起動すると、**その人が書いたスクリプトが自分のPCで動く**ことになります。  

各ツールはこの点を意識していて、VS CodeはWorkspace Trust、Codexはフック定義ごとのレビューと信頼を挟みます。  
それでも、確認するのは自分です。  

- 他人のリポジトリの`.claude/settings.json`や`.github/hooks/`は、エージェントを起動する前に中身を読む
- フックのスクリプトをAIが編集できる状態にしない。編集されると、次の呼び出しからその内容で動きます

skillsの回で書いた「配布元を確認する」と同じ話です。実行されるものが指示文からスクリプトに変わった分、影響は直接的になります。  

## 試してみる

フックを1つだけ入れて、わざと引っかけて止まることを確認します。  
効いているかどうかは、止まるまで分かりません。  

1. 空のフォルダで`git init`し、適当なファイルを1つコミットする。リモートは設定しない
2. 前述の設定とスクリプトを置く
3. エージェントに`git push --force origin main`を実行するよう頼む

止まれば、フックの拒否理由が表示され、AIはその理由を受けて別の行動をとります。  
止まらなければ、上の「フックが止まらないケース」を順に確認します。Claude Codeでは`/hooks`で読み込まれている設定を一覧できます。  

:::tip
リモートを設定していないので、仮にフックが効いていなくても`git push`は失敗するだけです。
確認用の環境で試してから、実際のリポジトリに入れてください。
:::

hooksは、入れれば安心になる道具ではありません。  
何を止めたいかを自分で決めて、止まることを自分で確かめる。その手間の分だけ、AIに任せられる範囲が広がります。
