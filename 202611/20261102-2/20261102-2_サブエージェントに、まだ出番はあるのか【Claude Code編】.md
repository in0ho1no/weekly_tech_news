# サブエージェントに、まだ出番はあるのか【Claude Code編】

:::warning
業務でのAI利用は各所属のルールに従ってください。
:::

:::caution
Claude Team Standard・Premiumユーザ向けに書いています。
:::

## はじめに

### この記事で扱うこと

Claude Codeでは、`.claude/agents/`にファイルを置くと、特定の作業を任せる専用のエージェント（カスタムサブエージェント）を定義できます。  
一方で、2026年10月22日にClaudeの公式サイトで公開された記事では、作業をサブエージェントに分けるより、1つのエージェントにSkillやツールを持たせる方が、よい結果になることが多かったと報告されています。  

本記事では、Claude Codeを対象に、次の3点を整理します。  

- まずはメインの会話とSkillで足りることが多い
- それでもサブエージェントが向いている場面がある
- 作るなら、最小限の定義から始められる

読み終えると、サブエージェントを作る前に「本当に分ける必要があるか」を判断でき、作る場合も短い定義ファイルから試せるようになります。  

:::caution
本記事は2026年10月31日時点の公式ドキュメントをもとに作成しています。
:::

### きっかけの記事について

きっかけの記事は、企業向けにAIエージェントを構築する人に向けたものです。  
1つのエージェントにまとめる方がよくなった理由として、次の点が挙げられています。  

- Skillやツールは、短い説明だけを先に見せ、必要になったときに中身を読み込めるようになった
- 1つのコンテキストで作業全体を見渡せる。サブエージェントからは要約しか戻らず、受け渡しの途中で情報が落ちる
- モデルの性能が上がり、1つのエージェントで扱える範囲が広がった

ただし、サブエージェントを否定しているわけではありません。  
分けた方がよくなるかを確かめ、よくなる場合だけ残す、という立場です。  

:::source
Claude「Building agents: When to fold subagents into your main agent loop」
<https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop>
:::

## まずはメインの会話で足りるか

### サブエージェントの動き

サブエージェントは、メインの会話とは別のコンテキストで動きます。  
メインの会話の履歴、呼び出し済みのSkill、Claudeが読んだファイルは、サブエージェントからは見えません。  
Claudeが作業内容をまとめて渡し、サブエージェントの作業が終わると、その要約だけがメインの会話に戻ります。  

サブエージェントが送るリクエストも、メインの会話と同じ利用上限に数えられます。  

### Skillとの使い分け

公式ドキュメントでは、次のように使い分けが説明されています。  

メインの会話が向いているとき：

- やり取りを重ねながら、少しずつ仕上げていく
- 複数の段階で、多くの文脈を共有する
- すぐ終わる、小さな変更をする
- 応答の速さを重視する（サブエージェントは毎回まっさらな状態から始まるため）

サブエージェントが向いているとき：

- 作業の途中で、メインの会話には要らない長い出力が出る
- 使えるツールや権限を絞りたい
- 作業が単独で完結し、要約を返せば済む

繰り返し使う手順を残したいだけなら、Skillで足ります。  
Skillは、メインの会話の中で動く手順です。サブエージェントのように、会話から切り離されるわけではありません。  

:::source
Claude Code Docs「Create custom subagents」
<https://code.claude.com/docs/en/sub-agents>
:::

## それでも出番がある場面

### 途中の出力をメインに持ち込まない

テストのログ、検索の結果、たくさんのファイルの中身などは、作業の途中では必要でも、あとの会話ではほとんど使いません。  
こうした作業をサブエージェントに任せると、メインの会話には要約だけが戻り、コンテキストの枠を空けておけます。  

その代わり、戻ってくるのは要約です。細かいところは落ちることがあります。  
あとで細部まで使う作業は、メインの会話で進める方が向いています。  

### 独立した作業を並べる

サブエージェントは、バックグラウンドで同時に動かすこともできます。  
互いの結果を必要としない調べものを、並べて進めたいときに使えます。  

:::sample

```text
認証、データベース、APIの各モジュールを、別々のサブエージェントで並行して調べて
```

:::

並べたサブエージェントの結果は、それぞれメインの会話に戻ります。  
公式ドキュメントでは、多くのサブエージェントがそれぞれ詳しい結果を返すと、メインのコンテキストを大きく消費すると注意されています。  
また、ある作業の結果を次の作業が使うような、つながった作業は並べるのに向きません。  

### 使うモデルを決めておく

サブエージェントの定義ファイルでは、`model`で使うモデルを指定できます。  

| 書き方 | 使われるモデル |
| :- | :- |
| `sonnet`・`opus`・`haiku`・`fable`、またはモデルの正式なID | 指定したモデル |
| `inherit`、または`model`を省略 | メインの会話のモデル |

`model`を指定しておくと、メインの会話でどのモデルを選んでいても、その作業は決まったモデルで動きます。  
読むだけの調査は軽いモデルに任せる、確認役は強いモデルにする、といった使い方ができます。  

ただし、Claudeがサブエージェントを呼び出すときにモデルを指定した場合は、そちらが優先されます。  
定義ファイルの`model`は「必ずこのモデルで動く」という保証ではなく、優先順位の1つと考えておきます。  

## やってみよう

### 最小の定義ファイルを書く

読むだけの調査を任せるサブエージェントを作ってみます。  
業務のコードではなく、試し用のフォルダで試すことをおすすめします。  

プロジェクトのフォルダに`.claude/agents/code-researcher.md`を作り、次の内容を書きます。  

:::sample

```markdown
---
name: code-researcher
description: コードを読むだけの調査を任せるときに使う。関係するファイルのパスと、短い要約を返す。
tools: Read, Glob, Grep
model: haiku
---

指定されたテーマについて、ファイルを変更せずに調べてください。
関係するファイルのパスと、分かったことを短くまとめて返してください。
分からなかった点は、分からなかったと書いてください。
```

:::

| 項目 | 内容 |
| :- | :- |
| `name` | サブエージェントの名前（必須） |
| `description` | どんなときに任せるか（必須）。Claudeはこれを見て、任せるかどうかを決める |
| `tools` | 使えるツール。ここではファイルを読む・探す系に絞っている |
| `model` | 使うモデル。ここでは軽いモデルの`haiku` |

`---`(フロントマター)より下の本文が、サブエージェントへの指示になります。  
すべてのプロジェクトで使いたい場合は、`~/.claude/agents/`に置きます。  

:::caution
フロントマターの項目名を書き間違えても、エラーにはならず、その項目は無視されます。  
指定したはずの設定が効いていないと感じたら、項目名の綴りを確認します。
:::

### 呼び出して、戻ってきたものを見る

1. Claude Codeで`@`を入力し、候補から`code-researcher`を選ぶ。
2. 続けて、調べてほしいことを書いて送る。
3. メインの会話に戻ってきた結果を読む。
4. `/context`で、コンテキストの枠の埋まり方を確認する。

:::sample

```text
@"code-researcher (agent)" 設定ファイルを読み込んでいる箇所を調べて
```

:::

`@`で選ぶと、そのサブエージェントが必ず使われます。  
「code-researcherサブエージェントを使って調べて」のように、言葉で頼むこともできます。  

同じ調べものをメインの会話で頼んだ場合と、`/context`の表示を見比べてみるのも1つの方法です。  
どの程度の差が出るかは、調べる内容やフォルダの大きさによって変わります。  

### 利用量に気を配る

サブエージェントの利用量も、Teamプランの利用上限に含まれます。  
並べる数が増えるほど、そのぶん利用量も増えます。利用状況は`/usage`で確認できます。  

試してみて、メインの会話で頼むのと変わらないと感じたら、定義ファイルを消してメインの会話に戻せば十分です。
