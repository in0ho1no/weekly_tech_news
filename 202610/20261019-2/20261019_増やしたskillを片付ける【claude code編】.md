# 増やしたSkillを片付ける【Claude Code編】

:::warning
業務でのAI利用は各所属のルールに従ってください。
:::

:::caution
Claude Team Standard・Premiumユーザ向けに書いています。
:::

## きっかけ

### Skillが増えてきたら

Skillは、作り始めると少しずつ増えていきます。  
試しに作ったもの、似た作業用にもう1つ作ったもの、作ったきり使っていないものが混ざってくると、「思った場面で、思ったSkillが使われない」ことが起きやすくなります。  

本記事では、Claude Codeで使うSkillを対象に、次の2点を整理します。  

- Skillは置き場所によって、誰に効くかが決まる
- Skillは増やすほど、1つ1つが選ばれにくくなる

あわせて、手持ちのSkillを棚卸しする手順を紹介します。  
読み終えると、自分のSkillを「どこに置き、どれを残すか」を自分で判断できるようになります。  

:::caution
本記事は2026年10月18日時点の公式ドキュメントをもとに作成しています。
:::

## 置き場所で、効く範囲が決まる

### 個人用とプロジェクト用

Claude CodeのSkillは、主に次の2か所に置きます。  

| 置き場所 | パス | 誰に効くか |
| --- | --- | --- |
| 個人用 | `~/.claude/skills/<Skill名>/SKILL.md` | 自分だけ。どのプロジェクトで起動しても使われる |
| プロジェクト用 | `.claude/skills/<Skill名>/SKILL.md` | そのリポジトリでClaude Codeを使う人全員 |

`~`はホームフォルダを表します。Windowsでは`C:\Users\<ユーザ名>`にあたります。  

個人用に置いたSkillは、どのプロジェクトで作業していても候補になります。  
特定のプロジェクトでしか使わないSkillを個人用に置いておくと、関係のない作業のときにも選択肢に並ぶことになります。  

:::source
Claude Code Docs「Extend Claude with skills — Where skills live」
<https://code.claude.com/docs/en/skills#where-skills-live>
:::

### チームで使うものはプロジェクトに置く

チームの誰もが使う手順をSkillにしたなら、プロジェクト用の`.claude/skills/`に置き、リポジトリにコミットします。  
各自が同じSkillを個人用にコピーして持つ形にすると、誰かが直しても、ほかの人の手元には古い版が残ります。  
プロジェクトに置いておけば、直した内容はGitを通じて全員に届き、変更の履歴も残ります。  

ただし、プロジェクトに置いたSkillは、そのリポジトリでClaude Codeを使う人全員の候補に並びます。  
自分のやり方に合わせたSkillをそのまま持ち込むのではなく、チームで使う内容かどうかを確かめてから置きます。  

個人用からプロジェクト用へ移すときは、コピーではなく移動にします。  
Claude Codeでは、同じ名前のSkillが個人用とプロジェクト用の両方にあると、個人用が優先されます。  
個人用に古い版を残したままだと、チームで直したプロジェクト用の版は、自分の手元では使われません。  

:::source
Claude Code Docs「Extend Claude with skills」
<https://code.claude.com/docs/en/skills>
:::

## 増やすほど、選ばれにくくなる

### descriptionは最初から読み込まれている

Claude Codeは、セッションを始めた時点で、Skillの名前とdescriptionを読み込みます。  
`SKILL.md`の本文は、Skillが使われるときに初めて読み込まれます。  
Claudeは、この名前とdescriptionを手がかりに、今の依頼にどのSkillを使うかを判断します。  

公式ドキュメントでは、一覧に載ったSkillはどれも、実際に使われるかどうかに関係なく、毎回のやり取りでコンテキスト（AIが一度に扱える情報の枠）を使うと説明されています。  
使っていないSkillも、置いてあるだけで枠の一部を使っていることになります。  

:::source
Claude Code Docs「Extend Claude with skills — Control who invokes a skill」
<https://code.claude.com/docs/en/skills#control-who-invokes-a-skill>
:::

### 似たSkillが並ぶと、判断がぶれる

たとえば「議事録をまとめる」Skillと「会議メモを整理する」Skillが両方あると、descriptionだけでは違いが伝わりにくくなります。  
こうなると、同じような依頼でも使われるSkillが毎回変わったり、意図していない方が使われたりします。  
Skillの数が増えるほど、こうした似た組み合わせも生まれやすくなります。  

これはSkillの中身の問題ではなく、並び方の問題です。  
1つ1つのSkillを丁寧に書いていても、似たものが並べば、選び分けは難しくなります。  

### 使っていないSkillを消すのは損ではない

作ったSkillを消すのは、もったいなく感じるかもしれません。  
ただ、使っていないSkillも、コンテキストを使い、選ぶときの比較対象にも毎回含まれます。  
残しておくことで、使いたいSkillの選び分けを難しくしていることもあります。  

プロジェクト用のSkillはGitの履歴から戻せます。  
個人用のSkillも、必要になったときに改めて作れば、そのときの作業に合った内容で作り直せます。  

消すか迷うSkillは、front matterに`disable-model-invocation: true`を指定する方法もあります。  
Claudeが自動で使うことはなくなり、`/`から自分で呼び出したときだけ使われます。  
この指定をしたSkillは、descriptionも最初の読み込みから外れます。  

## 試してみる

### 手持ちのSkillを棚卸しする

すでにSkillを使っていれば、手持ちのSkillで一度棚卸しをしてみるといいでしょう。  

1. Skillを置いているプロジェクトでClaude Codeを起動し、`/skills`と入力して一覧を見る。(確認のみ)
2. 確認を終えたらClaudeに次のように頼む。
3. 返ってきた指摘を読み、Skillごとに「個人用のまま」「プロジェクトへ移す」「消す」を自分で決める。

:::sample

```text
~/.claude/skills/ と、このプロジェクトの .claude/skills/ にあるSkillについて、
名前とdescriptionを表にしてください。
そのうえで、役割が重なっているものと、どの場面で使うのか曖昧なものを挙げ、理由を添えてください。
ファイルは変更しないでください。
```

:::

最後の一文は、Claudeが指摘ついでにSkillを書き換えたり消したりしないようにするためのものです。  

手順3の判断は、Claudeの指摘をそのまま採用せず、自分で行います。  
指摘はAIによる分析なので、毎回同じ結果になるとは限らず、すべてが的確とも限りません。  
そのSkillを誰が、どの場面で使っているかを知っているのは自分です。  

判断に迷ったときは、次の問いが目安になります。  

| 問い | 当てはまるなら |
| --- | --- |
| このリポジトリでしか使わないか、チームの誰もが使うか | プロジェクトへ移す |
| しばらく使っていないか、別のSkillと役割が重なっているか | 消す（迷うなら自分で呼び出すときだけにする） |
| どのプロジェクトでも、自分だけが使うか | 個人用のまま |

重なっていると指摘された2つを残す場合は、descriptionに「どんなときに使い、どんなときは使わないか」を書き分けておくと、選び分けがぶれにくくなります。
