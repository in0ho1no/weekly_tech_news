# 答えるAIから、任されるAIへ

## きっかけ

### 3社が、同じ方向へ

9月中旬から10月初めにかけて、OpenAI・Anthropic・GitHubが相次いで新しい機能を発表しました。  
製品の形はそれぞれ違いますが、どれもAIにひとまとまりの作業を任せ、AIがそれを進めていく使い方を広げるものです。  

これまでのチャットAIは、聞かれたことに答えるやり取りが中心でした。  
そこから、任された作業を続けて進める方向へ、使い方の幅が広がりつつあります。  

今回は、3社の発表を並べて、次の点を整理します。  

- 3社がそれぞれ何を発表したか
- 3つに共通している変化
- 任せる範囲が広がるなかで、人の確認がどこに置かれているか

:::info
いずれの機能も、一部のプランから段階的に提供が始まっていたり、プレビューの段階だったりします。
ここでは個々の製品の使い方ではなく、流れの紹介として扱います。
:::

## 3社の発表

### OpenAI：会話の合間も動き続ける「dots」

9月29日、OpenAIは開発者向けイベント「DevDay」で、常時稼働するエージェント「dots」を発表しました。  
dotsは1回のやり取りで終わらず、会話と会話の間も、任された仕事を進め続けるという位置づけです。  

OpenAIの紹介では、次のような働き方が挙げられています。  

- クラウド上の専用のコンピュータとブラウザを使って作業する
- 連携したアプリの情報を、バックグラウンドで読み取って確認する
- 決めておいた予定に沿って、リマインドなどを実行する

提供はChatGPTのProとBusiness Premiumの利用者から、対象地域で順次始まっています。  
Enterprise向けは、管理者が有効にした場合のベータ版としての提供です。

<https://openai.com/index/introducing-dots/>

### Anthropic：ページを閉じても続く「Claude」

9月16日、AnthropicはClaudeのチャットと、作業を任せるための「Cowork」を1つに統合しました。  
利用者はモードを選び分ける必要がなく、1つの会話の中で、ちょっとした質問から調査や資料作成までを頼めます。  

時間のかかる作業はクラウド上で動き続けるため、ページやPCを閉じても止まりません。  
戻ってきたときには、結果が会話の中に届いている、という使い方です。  

提供はProとMaxプランから段階的に始まっており、ほかのプランは順次とされています。  
同じプランでも、使えるようになる時期はアカウントごとに異なります。

### GitHub：デスクトップのアプリを操作する「Copilot」

10月1日、GitHubはCopilotがデスクトップのアプリを操作できる機能「Computer Use」を、パブリックプレビューとして公開しました。  
画面の内容を読み取り、クリックや文字の入力、スクロールなどを行って、複数のアプリにまたがる作業を進められます。  
コマンドやAPIでは操作できず、画面操作が前提になっているソフトウェアでも、作業を任せられるようにするものです。  

対象はGitHub Copilot CLIと、macOS・Windows向けのGitHub Copilotアプリです。  

:::source

<https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/>
:::

## 3つに共通していること

### 任されて動く

3つの発表に共通するのは、AIにひとまとまりの作業を任せる使い方を広げている点です。  
ただし、その広げ方は製品ごとに異なります。  

| 製品・機能 | 作業を任せるうえでの特徴 | 広がる使い方 |
| --- | --- | --- |
| dots | 会話の合間も、任された仕事を進め続ける | その都度話しかけなくても、継続して仕事を進めてもらう |
| Claude | 質問と作業の依頼を1つの会話で扱い、ページやPCを閉じても作業を続ける | 調査や資料作成を頼み、後から結果を確認する |
| GitHub&nbsp;Copilot（Computer&nbsp;Use） | デスクトップのアプリを操作する | コマンドやAPIでは扱えない画面上の作業を任せる |

聞かれたら答える使い方がなくなるわけではありません。  
その延長に、任された作業を進める使い方が加わってきている、という変化です。  

なかでも、dotsのように継続して仕事を進めるエージェントには、先行例があります。  
Microsoftは6月、オープンソースのOpenClawを基盤にしたエージェント「Scout」を、先行プログラムの顧客向けに提供し始めています。  
Scoutは限られた顧客向けの提供ですが、今回の3社の発表で、ChatGPT・Claude・GitHub Copilotといった、多くの人が普段使う製品で、作業を任せる使い方を利用できる人が増え始めています。  

:::source
Microsoft「Microsoft Build 2026: 職場で自分らしく働く」（2026年6月3日）
<https://news.microsoft.com/source/asia/features/microsoft-build-2026-be-yourself-at-work/?lang=ja>
:::

### 人が確認する場所が用意されている

任せる範囲が広がるほど、AIが作業を進める途中のどこで人が確認するかが大事になります。  
3社とも、そのための承認の仕組みを用意していますが、確認する対象やタイミングは異なります。  

- dots：操作の種類ごとに「確認なしで進める」「事前に許可したものだけ進める」「実行前に確認する」「人に引き継ぐ」を決めておける。パスワードの変更のような作業は、常に人が行う
- Claude：初期設定では、アクションを実行する前に確認を求める。通常は確認を挟まずに作業を進め、注意が必要な場面で確認する設定にも切り替えられる
- GitHub Copilot（Computer Use）：アプリを操作する前に承認を求める。アプリごとに常に許可することもでき、その設定は後から見直したり解除したりできる。組織の設定で、機能そのものを無効にもできる

新しいAIの機能を目にしたときは、何ができるかとあわせて、どこで確認を求められるかも見ておくと、その機能の性格がつかみやすくなります。  

:::warning
業務でのAI利用は各所属のルールに従ってください。
:::
