# 架空の作業メモと改善確認手順

以下はすべて架空の情報です。両製品で、修正前後に同じ実行指示を使います。
メモをファイル参照で渡すのではなく、下のコードブロック内をチャットに貼り付けてください。

## 0. 専用フォルダに配置する

このリポジトリの外に、Claude Code用とGitHub Copilot Chat用の専用フォルダを別々に作ります。
各サンプルを、専用フォルダ内の次の場所にコピーします。

| 対象 | コピー元 | コピー先 |
| --- | --- | --- |
| Claude Code | [claude-demo.md](./claude-demo.md) | `.claude\skills\demo\SKILL.md` |
| GitHub Copilot Chat | [github-copilot-demo.md](./github-copilot-demo.md) | `.github\skills\demo\SKILL.md` |

元のサンプルは比較用に残し、改善作業はコピー先だけに反映します。
GitHub Copilot Chat用の分析拡張機能は、組織のルールに従って利用承認・導入を済ませてください。

## 1. 改善前に実行する

専用フォルダで新規セッションを開始し、次のコードブロック内をそのまま送信します。
応答は、後で比較できるよう手元に保存してください。

```text
/demo

以下の作業メモから、週報を作成してください。

対象週：2026年10月5日〜10月9日
担当者：架空の担当者A
プロジェクト：社内向け図書貸出アプリの試作

作業メモ：
- 貸出一覧画面の下書きを作成した。これは完了。
- 貸出一覧画面のレビューは未完了。レビュー担当者からの返答待ち。
- 返却日の表示不具合を修正した。修正は完了したが、動作確認は未完了。
- 動作確認が止まっている理由は、検証環境の準備がまだ終わっていないため。
- 利用手順の資料は全5節のうち3節を書いた。残り2節と全体レビューは未完了。
- チーム定例に参加し、議事メモを共有した。これは完了。
- 次週は、画面レビューの指摘が届いたら対応する。
- 次週は、検証環境の準備が整い次第、返却日の表示を確認する。
- 次週は、利用手順の残り2節を書き、全体レビューを依頼する。
- 各作業の所要時間、完了予定日、優先順位は記録していない。
```

## 2. 新規セッションで改善する

改善前の実行セッションは継続せず、同じ専用フォルダで新規セッションを開始します。
このセッションでは`/demo`を呼び出さず、点検と修正だけを行います。

- Claude Code：`/doctor prompt-audit .claude/skills/demo`を実行します。Claude Code v2.1.283以降と、点検に使う同梱Skillが有効であることが必要です。
- GitHub Copilot Chat：コピー先の`SKILL.md`を開き、「Chat Customizations Evaluations: Analyze Prompt」で分析します。

指摘を確認したあと、次の指示を送信します。
GitHub Copilot Chatでは、指摘された行と内容も同じチャットに貼り付けてください。

```text
点検対象のdemo Skillについて、指摘を踏まえて改善案を出してください。
まだファイルを変更しないでください。

日本語の週報を作るというゴールと、チャットに貼り付けたメモだけを使い、
記載されていない事実を追加しないという作業範囲は変えないでください。

出力形式の矛盾は「完了」「未完了」「次の予定」の見出しと箇条書きに統一してください。
情報の選び方と長さの基準を具体化し、入力がない場合や不足している場合の対応も明示してください。
修正対象は、この専用フォルダに配置したdemoのSKILL.mdだけです。
```

案を確認し、採用する内容を明示して反映を依頼します。
点検結果は毎回同じとは限らないため、指摘が出なかった箇所も含めて案を確認してください。

## 3. 新規セッションで改善後に実行する

改善作業のセッションは継続せず、同じ専用フォルダで新規セッションを開始します。
手順1のコードブロック内を一字も変えずに送信します。
比較時は、製品ごとに修正前後のモデルと関連設定をそろえてください。

### 比較する点

- 「完了」「未完了」「次の予定」の見出しと箇条書きで出力されるか。
- 画面の下書き作成とレビュー、表示不具合の修正と動作確認が、別の進捗として扱われているか。
- 資料全体を完了とせず、残り2節と全体レビューが未完了として扱われているか。
- 返答待ち・検証環境待ちと、次週の作業に付く条件が保たれているか。
- 記録されていない所要時間、完了予定日、優先順位を作り足していないか。

一度の結果だけでは改善の確実性までは判断できません。必要なら、同じ条件の新規セッションで繰り返します。
入力なしへの対応は、このメモを使う比較だけでは確認できません。別の新規セッションで`/demo`だけを送信して確認してください。
