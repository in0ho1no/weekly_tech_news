# スラッシュコマンドはSkillを呼び出すだけじゃない【Claude Code編】

:::warning
業務でのAI利用は各所属のルールに従ってください。
:::

:::caution
Claude Team Standard・Premiumユーザ向けに書いています。
:::

## はじめに

### この記事で扱うこと

Skillは、`/`とSkill名を入力すると、自分で呼び出せます。  
ただ、`/`を入力したときに並ぶ候補は、Skillだけではありません。  
会話を要約する、別のモデルに相談させるといった、作業の進め方を支えるコマンドも並んでいます。  

本記事では、Claude Codeを対象に、次の2点を整理します。  

- `/`に並ぶものには、Skillを呼び出すものと、Claude Codeに組み込まれたコマンドがある
- 組み込みのコマンドには、会話を整えるものや、別のモデルの視点を足すものがある

あわせて、自身のClaude Codeの使い方についてフィードバックを受け取る手順を紹介します。  
読み終えると、`/`の候補を、Skillの呼び出し口としてだけでなく、作業の進め方を整える道具としても使い分けられるようになります。  

:::caution
本記事は2026年10月26日時点の公式ドキュメントをもとに作成しています。
:::

## `/`に並ぶもの

### Skillを呼ぶもの

`/`の候補には、自分で作ったSkillもしくはClaude Codeに同梱されたSkillを呼び出せます。  
設定の不具合を診断する`/doctor`も、同梱されたSkillの1つです。  
同梱のSkillも、自分で作るSkillと同じく、Claudeに渡す指示として動きます。  

### 組み込みのコマンド

`/`の候補の多くは、Claude Codeに組み込まれたコマンドです。  
その中には、`/compact`のように会話を整えるものや、`/advisor`のように別のモデルの視点を足すものがあります。  

すべてのコマンドが、すべての人に表示されるわけではありません。  
公式ドキュメントでは、使えるコマンドは、使っている環境やプランによって変わると説明されています。  

:::source
Claude Code Docs「Commands」
<https://code.claude.com/docs/en/commands>
:::

## 会話を整える

### 長くなった会話を要約する：`/compact`

1つの会話でやり取りを続けると、それまでの内容がコンテキスト（AIが一度に扱える情報の枠）を少しずつ埋めていきます。  
`/compact`は、それまでの会話を要約して、この枠に空きを作るコマンドです。  
`/compact`のあとに、要約で残してほしい内容を書き添えることもできます。  

:::sample

```text
/compact 決めた仕様と、まだ解決していない課題を残して
```

:::

枠がどれくらい、何で埋まっているかは、`/context`で確認できます。  
Claude Codeは枠の上限が近づくと自動で会話を要約しますが、`/compact`を使えば、それを待たずに自分のタイミングで要約できます。  

要約するときには、Claudeがそれまでの会話を読み直します。会話が長いほど、要約そのものにも利用量がかかります。  
今の作業と関係のない作業に移るときは、要約するより、`/clear`・`/new`で新しい会話を始める方が向いています。  

:::source
Claude Code Docs「Manage costs effectively」
<https://code.claude.com/docs/en/costs>
:::

### 本筋を止めずに質問する：`/btw`

`/btw`は、会話の履歴に加えずに、今の作業について質問できるコマンドです。  
「さっきの設定ファイルの名前は何だったか」のような、本筋の流れに残すほどではない確認に使えます。  

:::sample

```text
/btw さっき話していた設定ファイルの名前は？
```

:::

`/btw`には、次の特徴があります。  

- Claudeが作業している最中でも使え、作業を止めない
- それまでの会話（自分のメッセージ、Claudeの返答、Claudeが読んだファイルなどの結果）をもとに答える
- ファイルを読む、コマンドを実行する、検索するといった操作はしない
- 質問と答えは、会話の履歴に残らない

新しく調べてほしいことがあるときは、`/btw`ではなく、通常のやり取りで頼みます。  

:::source
Claude Code Docs「Interactive mode — Side questions with /btw」
<https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw>
:::

## 別の視点を足す

### 別のモデルに相談させる：`/advisor`

`/advisor`は、作業中のClaudeが、要所で別の（多くはより強い）モデルに相談できるようにするコマンドです。  
相談役のモデルは、ツールの実行結果を含む会話全体を受け取り、助言を返します。Claudeはその助言をふまえて作業を続けます。  

相談するタイミングは、Claudeが決めます。  
公式ドキュメントでは、方針を決める前、同じエラーが繰り返されるとき、作業の完了を宣言する前などに相談する傾向があると説明されています。  
「相談してから進めて」のように、プロンプトで相談を頼むこともできます。  

相談役のモデルは、次のように指定します。  

:::sample

```text
/advisor opus
```

:::

引数を付けずに`/advisor`を実行すると、選べるモデルの一覧が表示されます。  
選べるモデルは、今使っているモデルによって変わります。  

:::caution
`/advisor`が使う相談役の機能は、実験的機能（experimental）です。今後、動きや料金の扱いが変わる可能性があります。
:::

:::source
Claude Code Docs「Escalate hard decisions with the advisor tool」
<https://code.claude.com/docs/en/advisor>
:::

### 利用量に気を配る

相談のたびに、相談役のモデルが会話全体を読むため、そのぶん利用量が増えます。  
Teamプランでは、この利用量もプランの利用上限に含まれます。  

`/advisor`で選んだ設定は保存され、次のセッションにも引き継がれます。  
有効になっている間は、セッションの開始時に、相談役の機能が有効で利用量が増える可能性がある旨の通知が表示されます。  
必要な作業が終わったら、`/advisor off`で止めておきます。  

:::sample

```text
/advisor off
```

:::

利用状況は`/usage`で確認できます。  

## やってみよう

ここまでは、今の作業を進めるためのコマンドを紹介しました。  
最後に、これまでの使い方を振り返るコマンドを試してみます。  

### 自分の使い方へのフィードバックを読む：`/insights`

`/insights`は、このPCでの最近のセッションを分析し、使い方のレポートを作るコマンドです。  
レポートには、どんな作業に使っているか、依頼が誤解された場面などのつまずき、Claude Codeをより効果的に使うための提案がまとめられます。  

1. Claude Codeで`/insights`を実行する。
2. 作成されたレポートをブラウザで開く。（出力パスは表示されるはずです）
3. 書かれている提案を読み、自分の使い方に当てはまるかを自分で判断する。

分析にも利用量がかかり、プランの利用上限に含まれます。  
レポートはAIによる分析なので、毎回同じ結果になるとは限らず、すべてが的確とも限りません。  
自分がどんな作業にClaude Codeを使っているかを知っているのは自分です。気になった提案を1つ選び、次の作業で試してみる程度で十分です。  

:::info
レポートには、業務で扱った作業の内容が含まれることがあります。共有する場合は、社内ルールに従ってください。
:::
